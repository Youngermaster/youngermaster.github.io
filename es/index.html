Sobre mí

¿Problemas? Dalos por resueltos y programados

Construyo las partes de un sistema que tienen que seguir funcionando cuando nadie está mirando.

Ahora mismo eso significa liderar una plataforma de interoperabilidad en salud que permite a los prestadores colombianos cumplir un mandato nacional — un pipeline basado en colas, con microservicios NestJS que producen registros HL7 FHIR R4, diseñado para sobrevivir a una API gubernamental que rara vez es rápida o está disponible.

Antes de eso: React Native y Next.js en producción en Publicis, red teaming y DevSecOps en Aligo y Geta Club Play, y una década dando clases particulares que sigue siendo la razón por la que puedo explicar cualquiera de estas cosas. Fuera del trabajo escribo librerías de robótica en Rust y publico aplicaciones móviles con Grisú.

Tecnologías

  • Rust

    Mi opción por defecto para sistemas — drivers de robótica, SLAM y todo lo que tenga que correr en una Raspberry Pi sin arrastrar un toolchain de C++.

  • Python

    Servicios de backend, trabajo de IA, automatización y el web scraping en el que me apoyo desde mis años en seguridad.

  • React Native

    Donde vive la mayor parte de mi trabajo móvil — apps de e-commerce en Publicis y las aplicaciones que publico con Grisú.

  • React

    La mitad web de la misma historia: front ends en producción, componentes de design system y algún panel administrativo interno.

  • FastAPI

    Mi elección cuando un servicio en Python debe escribirse rápido, con tipos y documentado sin ceremonia adicional.

  • Docker

    Cómo todo lo que construyo se vuelve reproducible — desde un scraper puntual hasta un monorepo de microservicios.

  • AWS

    Donde corren las cargas de producción, junto con los pipelines de CI/CD y la observabilidad que los vigila.

  • Linux

    Mi sistema de trabajo desde la universidad, y el entorno donde termina ejecutándose casi todo lo que escribo.

  • MongoDB

    Almacenamiento documental para la plataforma de interoperabilidad en salud, donde la forma de un registro clínico es todo menos fija.

  • PostgreSQL

    Mi base de datos relacional por defecto — cuando los datos tienen una forma que vale la pena hacer cumplir, van aquí.

  • Apache Kafka

    Streaming de eventos para pipelines que no pueden permitirse perder un mensaje, como la telemetría de EcoDrive.

  • GraphQL

    Lo uso cuando un cliente necesita hacer preguntas precisas sobre un grafo de datos en vez de encadenar cinco llamadas REST.

  • MQTT

    La columna vertebral de mensajería en mi trabajo de IoT — liviano para un microcontrolador y confiable para diseñar un sistema alrededor.

  • Raspberry Pi

    El objetivo habitual del trabajo de robótica: compilar el Rust de forma cruzada, enviarlo a la Pi y ver girar el lidar.

  • Arduino

    Donde empezó el lado hardware — el sistema de riego automatizado que ganó el tercer puesto en Expo-Ingenierías funcionaba con uno.

  • Jenkins

    CI/CD en los lugares que ya lo usan; GitHub Actions y GitLab CI cubren el resto.

  • Godot

    El motor detrás de los juegos móviles hyper-casual que construyo en Grisú — libre, pequeño y rápido para iterar.

  • Neovim

    Mi editor. Configurado una vez, llevado a todas partes, y más rápido que estirar la mano hacia el mouse.

  • Obsidian

    Donde viven las notas de arquitectura, la investigación y las ideas a medio formar antes de convertirse en código.

  • Figma

    Para el trabajo de UI — diseñar la interfaz antes de construirla, como hice para GameConnect.

Líder Técnico

dic de 2025 — Actualidad· 9 meses

Tiempo completo · Híbrido · Medellín, Antioquia, Colombia

  • Lideré el diseño y la entrega de una plataforma de interoperabilidad en salud a escala nacional que permite a los prestadores colombianos cumplir la Resolución 1888 de 2025, que exige el Resumen Digital de Atención en Salud (RDA) para historias clínicas electrónicas usando HL7 FHIR R4.
  • Entregué un pipeline de generación de RDA totalmente conforme antes del plazo nacional, con un backend arquitecturado como monorepo Turborepo de microservicios NestJS que coordinan las etapas de envío, validación, conversión y generación mediante colas de mensajes.
  • Mantuve la integridad de los datos y el cumplimiento normativo pese a una API gubernamental poco confiable, incorporando tolerancia a fallos y reanudación en el sistema de colas para que los envíos en curso se recuperen cuando la plataforma nacional está lenta o caída.
  • Reduje el costo de validar códigos de salud repetidos con una capa de caché en Redis con intervalo de refresco configurable, evitando revalidar los mismos códigos clínicos en cada petición y manteniendo el pipeline rápido bajo carga sostenida de múltiples prestadores, junto a persistencia en MongoDB.
  • Entregué las capacidades centrales de la plataforma contra un plazo de cumplimiento nacional inamovible, liderando un equipo de ingeniería multidisciplinario a través del diseño, la implementación y la entrega.
  • Hice confiable la operación en producción sobre AWS con un pipeline de CI/CD en GitHub Actions y observabilidad completa de logs, trazas y métricas usando Grafana, Loki y el stack LGTM.
